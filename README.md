# بوت تحميل فيديوهات بحد 2 جيجا (Telethon - حساب شخصي)

هذا الإصدار يستخدم حسابك الشخصي على تيلجرام (بدل بوت عادي) عشان يقدر
يرسل ملفات لغاية **2 جيجا** بدل حد 50 ميجا.

⚠️ **تنبيه:** هذا استخدام غير رسمي لحسابك حسب شروط تيلجرام. للاستخدام
الشخصي الخفيف الخطر منخفض، لكن المسؤولية عليك بالكامل.

---

## 1. احصل على API_ID و API_HASH

1. روح لـ https://my.telegram.org وسجل دخول برقم هاتفك (يرسلولك كود على تيلجرام).
2. اضغط **API development tools**.
3. عبّي أي اسم لأي تطبيق (مثلاً App title: MyBot, Short name: mybot).
4. بعد الإنشاء بيطلع لك **api_id** (رقم) و **api_hash** (نص طويل) — احفظهم.

---

## 2. ولّد Session String (على جهازك، مرة واحدة فقط)

هذا يحتاج تشغيله على جهازك الشخصي (كمبيوتر) لأنه يحتاج تفاعل منك
(إدخال كود التحقق).

1. ثبّت بايثون على جهازك إذا ما عندك (python.org).
2. افتح Terminal / Command Prompt واكتب:
   ```
   pip install telethon
   ```
3. حمّل ملف `generate_session.py` (المرفق) وشغّله:
   ```
   python generate_session.py
   ```
4. بيطلب منك API_ID و API_HASH (من الخطوة 1) ثم رقم هاتفك ثم كود
   التحقق اللي بيوصلك على تيلجرام.
5. بالنهاية بيطبع لك سطر طويل جدًا (Session String) — **انسخه واحفظه**،
   هذا يعادل تسجيل دخولك الكامل، لا تشاركه مع أي أحد.

---

## 3. ارفع الكود على GitHub

في نفس مستودعك اللي سويته قبل (`Mybotdown`)، استبدل/أضف الملفات:
- `telethon_bot.py`
- `requirements.txt` (المحدث)
- `Dockerfile` (المحدث)

يمكنك حذف `bot.py` القديم إذا حبيت، أو تركه بدون استخدام.

---

## 4. أنشئ خدمة جديدة على Render (أو عدّل الحالية)

نفس خطوات المرة اللي فاتت:
1. **New + → Web Service** → اختر نفس المستودع.
2. تأكد إن **Language** مضبوط على **Docker**.
3. Instance Type: اختر **$0/month (Free)**.
4. أضف متغيرات البيئة التالية (Environment Variables):
   - `API_ID` = الرقم اللي أخذته من my.telegram.org
   - `API_HASH` = النص اللي أخذته من my.telegram.org
   - `SESSION_STRING` = السطر الطويل اللي طبعه لك generate_session.py
   - `GROUP_CHAT_ID` (اختياري) = راجع القسم 7 لو تبي تستخدم البوت من
     أرقامك الأخرى عبر مجموعة خاصة
5. اضغط **Deploy web service**.

---

## 5. طريقة الاستخدام

1. افتح تيلجرام على جوالك، روح لمحادثة **Saved Messages** (رسائلي المحفوظة).
2. أرسل رابط فيديو (من X أو أي موقع مدعوم من yt-dlp).
3. البوت (يشتغل بحسابك) بيرد عليك بنفس المحادثة برسالة "جاري التحميل"
   ثم يرسل الفيديو نفسه.

---

## 6. تحميل فيديوهات تتطلب تسجيل دخول (كوكيز) - اختياري

بعض المحتوى على X (حسابات خاصة، محتوى مقيّد بعمر) ما يقدر yt-dlp يوصله
بدون "كوكيز" حساب مسجّل دخول فيه أصلاً. هذي الخطوات تخليك تزوّد البوت
بكوكيز حسابك بأمان (عبر متغير بيئة، بدون رفع أي ملف حساس لـ GitHub).

⚠️ **تحذير أمان:** الكوكيز تعادل تسجيل دخولك الكامل بحسابك على X. لا
تشاركها مع أي أحد ولا ترفعها لأي مكان عام. استخدم حساب X ثانوي إذا
كان عندك حذر إضافي.

### أ) صدّر الكوكيز من متصفحك

1. سجّل دخول لحسابك على **x.com** من متصفح Brave أو Chrome على جوالك
   أو كمبيوترك.
2. ثبّت إضافة (Extension) اسمها **"Get cookies.txt LOCALLY"**:
   - على الكمبيوتر: من متجر إضافات Chrome/Brave.
   - على الجوال: Brave للجوال يدعم إضافات Chrome عبر إعدادات خاصة، أو
     استخدم كمبيوتر لهذي الخطوة فقط إذا كانت أسهل لك.
3. وانت بصفحة x.com المسجّل دخول فيها، اضغط على أيقونة الإضافة.
4. اختر تصدير الكوكيز لموقع **x.com** فقط، وحمّل ملف باسم `cookies.txt`.

### ب) رمّز الملف بصيغة Base64

لازم نحوّل الملف لنص واحد طويل عشان نقدر نحطه كمتغير بيئة على Render.

**على جهاز كمبيوتر (Windows/Mac/Linux) عبر Terminal:**
```bash
base64 -i cookies.txt -o cookies_b64.txt
```
(على ويندوز عبر PowerShell:)
```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("cookies.txt")) | Out-File cookies_b64.txt
```

**أو على الجوال عبر Termux:**
```
cd storage/downloads
base64 -w 0 cookies.txt > cookies_b64.txt
cat cookies_b64.txt
```
انسخ الناتج الطويل اللي يطبعه لك.

### ج) أضفه كمتغير بيئة على Render

1. روح لصفحة الخدمة على Render → **Environment**.
2. أضف متغير جديد:
   - Key: `COOKIES_B64`
   - Value: الصق النص الطويل اللي حصلت عليه بالخطوة السابقة
3. احفظ، Render رح يعيد النشر تلقائيًا.

بعد هذا، البوت رح يقدر يحمّل أي محتوى يتطلب تسجيل دخول بحسابك تلقائيًا.

### د) تحديث الكوكيز لاحقًا

الكوكيز تنتهي صلاحيتها بعد فترة (أسابيع لشهور حسب إعدادات X). لو رجع
البوت يفشل بتحميل محتوى مقيّد بعد ما كان يشتغل، كرر خطوات أ وب وج
بكوكيز جديدة.

---

## 7. استخدام البوت من أرقامك الأخرى عبر مجموعة خاصة - اختياري

لو تبي ترسل روابط من أرقام تيلجرام ثانية عندك (مو بس من رقم Saved
Messages الأساسي)، وتستقبل الفيديوهات بنفس مكان الطلب:

1. أنشئ **مجموعة خاصة جديدة** بتيلجرام (New Group).
2. أضف لها: حسابك اللي شغّل عليه البوت (نفس رقم SESSION_STRING) +
   أرقامك الثانية اللي تبي ترسل منها روابط. **لا تضيف أي رقم غريب**
   لأن أي عضو بالمجموعة يقدر يشغّل البوت.
3. شغّل `get_group_id.py` على جهازك (بنفس API_ID/API_HASH/SESSION_STRING)
   عشان يطبع لك قائمة محادثاتك، ودوّر على اسم المجموعة الجديدة وانسخ
   رقم `chat_id` المقابل لها بالضبط (يشمل الإشارة السالبة إن وجدت).
4. روح لصفحة الخدمة على Render → **Environment** → أضف متغير جديد:
   - Key: `GROUP_CHAT_ID`
   - Value: الرقم اللي نسخته بالخطوة السابقة
5. احفظ، Render رح يعيد النشر تلقائيًا.

بعد كذا، أي رابط يرسله أي رقم من الأرقام المضافة بهذي المجموعة يتعامل
معه البوت بنفس طريقة Saved Messages بالضبط (تحميل، قائمة اختيار
جودة، أوامر التحكم زي "الغاء" و"حالة")، والفيديو النهائي يوصل لنفس
المجموعة مباشرة.

**ملاحظة:** أوامر مثل "الغاء" و"اعادة تشغيل" تشتغل على مستوى البوت
كله (نفس السيرفر)، مو منفصلة لكل رقم أو محادثة - يعني "الغاء" من
المجموعة يوقف أي تحميل جارٍ حتى لو بدأ من Saved Messages، والعكس صحيح.

---

## ملاحظات مهمة

- الحد الأقصى 2 جيجا (أو 4 جيجا لو حسابك Telegram Premium — عدّل
  MAX_FILE_SIZE في الكود لو عندك بريميوم).
- لا ترفع `SESSION_STRING` أو `API_HASH` لأي مكان عام؛ خلّيهم فقط في
  Environment Variables على Render.
- لو ظهرت مشاكل تسجيل دخول متكررة أو تنبيه أمني من تيلجرام، هذا طبيعي
  أول مرة تستخدم Session String من سيرفر جديد — وافق على الإشعار من
  جهازك إذا وصلك.
- حدّث yt-dlp بشكل دوري في requirements.txt لأن مواقع التواصل تتغيّر باستمرار.
